### 4. 设计语言参考（非开源，只学设计）

- **Slay the Spire**：肉鸽卡牌的构筑循环标杆——每局差异（种子/路线三选一）、遗物联动、失败即重开的学习曲线。本作的 10 层路线图 + 奖励三选一已是同构设计。

## 二、伟大作品的共性规律（从上述参考提炼）

1. **内容管线决定上限**：CDDA 靠 JSON 让内容和引擎解耦，SPD 靠多年版本节奏堆内容。手写 Java 枚举/硬编码事件永远到不了 50 事件以上的量级。
2. **长期主义**：Mindustry 与 SPD 都是单人 + 8~10 年。作品是马拉松，版本节奏比爆发力重要。
3. **传播是设计出来的**：lifeRestart 的"一句话结局 + 十连抽天赋"天然适合分享。肉鸽的种子、构筑、结局天然有分享基因，要主动暴露它。
4. **发布渠道即增长**：itch.io / Steam / F-Droid / HelloGitHub / README 英文版，每多一个渠道就多一个世界。
5. **社区友好是复利**：可读源码 + 数据驱动内容 + 明确的贡献文档 = 别人替你做内容。

## 三、路线图

### 阶段一：V1.0 内容量产（对齐 DEVELOPMENT_PLAN 的 V1.0 验收）

目标：把"功能完成"变成"内容成立"，达到可发布的最低内容密度。

1. **内容管线改造（最优先，学 CDDA + ink）**
   - 事件、功法/天赋、法宝/消耗品、结局全部迁移为 `database/content/` 下的 JSON 数据文件；
   - 定义并文档化内容 schema（事件：触发条件/选项/效果/稀有度/流派加权；仿 JSON_INFO.md）；
   - 后端启动时加载 + schema 校验，坏数据拒绝启动并报出文件行号；
   - 为内容文件写一个 `content-lint` 校验脚本（学 CDDA 的 mod 校验思路）。
2. **内容量产（数值目标沿 V1.0 验收）**：≥50 事件、≥10 功法/天赋、≥20 法宝/消耗品、≥6 结局；四流派各至少一条能通关的成型构筑路线。
3. **工程收尾**：移动端适配（React 响应式 + 触控热区）、API 鉴权与参数校验、后端单测/接口测试/MySQL 集成测试、Docker Compose 一键启动、生产日志与异常监控。
4. **验收方式**：H2 + MySQL 双库联调全绿；新事件从"加一个 JSON 文件"到"进游戏"不需要改 Java 代码。

### 阶段二：可传播的发布（学 lifeRestart + vue-xiuxiangame）

1. **部署上线**：Docker Compose 部署到一台云主机（或前端 Vercel + 后端小水管），公开可玩链接。
2. **分享设计**：结算页生成"一句话战报 + 种子号 + 构筑流派"的可复制文本/分享卡；好友可输入种子号复现同一局。
3. **数值打磨**：建立平衡性电子表（流派胜率、节点期望、经济曲线），先自测 50 局记录数据。
4. **物料**：README 配 30 秒 GIF 演示（对齐我其他项目的动态架构图风格）、补英文版 README；提交 HelloGitHub 收录（vue-xiuxiangame 的路径）。
5. **发布节奏**：itch.io 网页版免费放出去，收集首批真实反馈。

### 阶段三：生态与长线（学 Mindustry + CDDA）

1. **Mod 支持**：内容 JSON 允许外部目录加载 + lint 校验，写 Modding 指南。
2. **每周挑战**：固定全局种子 + 排行榜（结算分已有，补上报与排名接口）。
3. **PWA**：加 manifest 与离线缓存，手机"安装"为应用。
4. **若热度成立**：学 Mindustry 双轨模式——仓库保持开源，Steam 上架付费版（成就/云存档/创意工坊增值）。
5. **可选差异化**：AI 生成事件（Daoyou/react 版方向）作为实验分支，不进主线。

### 贯穿纪律

- 沿用现有节奏：一个版本一个主题、中文 Commit、每版本验收清单勾选后再合并；
- 每完成一个阶段做一次 README/文档同步（本次全仓 README 统一的教训：文档滞后是债务）；
- 数值改动必须留痕（平衡表版本化）。
